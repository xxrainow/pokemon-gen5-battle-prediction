# 로컬 프로젝트 복원 조사 및 통합 제안

조사일: 2026-11-17. `Desktop/5-1/기계학습` 아래 `pokemon`, `pokemon_2`의 현존 파일을 읽었다. 여기서 복원은 파일과 코드로 작업 흐름을 재구성한 것을 뜻한다. 삭제된 파일을 복구하거나 전체 파이프라인을 재실행한 것은 아니다. 원본과 기존 README는 변경하지 않았고 업로드도 수행하지 않았다.

## 확인한 작업 흐름

1. `pokemon/log/download_gen5.sh`: 7개 포맷의 원본 로그 Parquet 9개 다운로드. OU는 3개 부분으로 나뉜다.
2. `pokemon/code/parse_logs.py`: 팀 미리보기의 종과 승패, 경기 중 공개된 기술·아이템·특성을 추출한다. 경기 전 정보와 경기 중 정보를 코드에서 구분한다.
3. `merge_external.py`: 도감·기술 CSV를 결합한다. `verify_merge.py`와 `combine_parts.py`는 결합 결과 확인과 부분 파일 통합을 지원한다.
4. `pokemon_2/prepare_basic.py`: 7개 포맷을 통합하고 경기 전 종·종족값·타입만 남긴다. 품질 보고서 기준 입력 856,296행에서 33,877행을 제외해 822,419행 × 113열을 저장했다. 피처 108개, 관리 정보 4개, 정답 1개다.
5. `build_stat_sample.py`: 첫 경기 한 건의 능력치 요약 피처 54개를 계산한다. 독립 계산, 슬롯 순서 불변성, 팀 교환, 메타데이터 독립성, 저장값 확인 코드와 결과가 있다.
6. 타입 구성·방어 상성 피처는 정의 후보 단계다. 전체 피처 생성, 데이터 분할, 학습·평가 코드는 두 폴더에서 발견되지 않았다.

`pokemon`은 수집·전처리 작업, `pokemon_2`는 이를 이어받은 기본 데이터·피처 설계 작업이다. 두 이름을 저장소 최상위에 그대로 두기보다 처리 단계에 따라 합치는 것을 권장한다.

pokemon-gen5-battle-prediction/

현재 코드 7개는 직접 실행하는 스크립트이므로 먼저 `scripts/`에 모으면 충분하다. 학습과 추론에서 공통 함수를 재사용하게 될 때 `src/pokemon_battle/` 패키지로 분리한다. 아직 없는 학습·모델 파일은 만들어진 것처럼 표시하지 않는다.

## 보존과 Git 업로드를 나누는 방법

전체 90개 파일은 5,019,246,434바이트(약 5.02GB, 4.67GiB)다. 이 중 macOS·편집기 부속 파일도 포함된다. 파일별 크기와 프로젝트 파일의 SHA-256은 `local-inventory.json`에 기록했다.

| 항목 | 현재 용량 또는 상태 | 권장 보관 |
|---|---|---|
| 원본 로그 Parquet 9개 | 약 1.94GB | 로컬 `data/raw/`, 다운로드 스크립트는 Git |
| 기존 전처리 Parquet·CSV 및 요약 | 약 2.41GB | 표는 로컬 `data/initial_dataset/`, 요약은 Git |
| 기본 표 및 피처 샘플 등 | 약 668MB | 전체 표는 로컬, 작은 설명·샘플·검사 결과는 Git |
| 코드·도감·기술 CSV·정의 문서 | 작은 텍스트 파일 | Git |
| `.DS_Store`, `.vscode/contriviewer/` | 편집기·운영체제 기록 | 업로드 제외 |

첫 통합 때 CSV와 Parquet를 모두 보존하되 Git에는 전체 표를 넣지 않는다. 정리 후 분석의 기본 형식은 Parquet로 정하고 CSV는 필요한 경우 내보내면 된다. 통합 표와 포맷별 표도 같은 데이터를 다른 단위로 저장한 결과이므로 배포 시 필수 파일을 명시한다. 전체 데이터까지 공유하려면 별도 데이터 저장소를 두고 버전·해시·받는 방법을 Git에 기록하는 구성을 제안한다.

## 재현을 위해 먼저 해결할 사항

- **경로 의존성:** `prepare_basic.py`의 기본 입력이 형제 폴더 `pokemon/data/original`을 가리킨다. 파일 이동 시 CLI 기본값과 예제를 함께 수정해야 한다. 다운로드 스크립트는 자기 위치에 파일을 저장하고, 결합·검사 코드에도 `external/` 등 상대 경로가 있다.
- **현재 중간 데이터와 과거 요약의 차이:** 기존 요약은 91열 파싱 결과를 설명하지만 기본 표 품질 보고서의 입력은 1,243열이다. Ubers 등 일부 행 수도 다르다. 보고서에 기록된 9개 입력 파일의 SHA-256은 현재 파일과 모두 일치한다. 다만 행이 달라진 정확한 처리 과정은 현존 코드·문서만으로 확정할 수 없다. 현재 중간 데이터를 보존하고 과거 요약을 현재 파일의 검사 결과로 취급하지 않아야 한다.
- **결합 경로:** `merge_external.py`는 기본적으로 별도 `_merged` 폴더로 출력하지만 현재는 결합된 파일이 `data/original`에 있다. 중간 파일을 교체한 과정은 별도 기록이 필요하다. 향후 `parsed → enriched → basic` 경로를 명시적으로 분리한다.
- **외부 데이터 생성 출처:** `pokedex.csv`, `moves.csv`는 있지만 이를 추출한 스크립트와 Showdown 소스 버전은 발견되지 않았다. 스냅샷을 보존하고 생성 기준을 추가해야 한다. 타입 상성표 파일은 발견되지 않았다. 전체 5세대 정확성을 검증한 상태로 간주하지 않는다.
- **실행 환경:** 확인한 외부 Python 의존성은 pandas, pyarrow다. 최초 조사 시에는 미설치 상태였다. 후속 통합에서 프로젝트 가상환경을 만들고 실행에 사용한 버전을 `requirements.txt`에 기록했다.
- **정보 누수 방지:** enriched의 기술·아이템·특성은 경기 중 공개 정보다. 학습은 기본 표의 명시된 피처 목록에서 시작한다. `winner`, `y`는 입력에서 제외하고 `uploadtime`은 우선 시간 분할용 관리 정보로 둔다.

## 통합 순서 제안

1. 원본 폴더는 유지한 채 현재 파일을 새 경로에 복사하고, 조사 해시와 대조한다. 편집기 기록은 제외한다.
2. 데이터 폴더를 Git에서 제외하도록 `.gitignore`를 먼저 만든다. 코드·외부 CSV·문서·작은 샘플만 추적한다.
3. 각 스크립트의 입출력 경로를 권장 구조에 맞추고 프로젝트 루트 기준 실행 명령을 문서화한다.
4. 작은 ZU 포맷으로 수집 이후 단계를 검증하고, 현재 중간 데이터와 재생성 결과의 행·컬럼 차이를 조사한다. 그 전까지 기존 파일을 덮어쓰지 않는다.
5. 기본 표와 능력치 샘플을 검증한 뒤 코드·문서 중심으로 첫 업로드를 한다. 전체 데이터 배포는 별도로 구성한다.

후속 통합 작업에서 제안한 코드·외부 CSV·보고서·샘플 18개를 저장소 구조에 맞게 복사하고 입출력 경로를 수정했다. 대용량 표와 원본 폴더는 그대로 보존한다. 아래 실행 검증 기록은 이번 통합 작업의 결과다.

## 통합 후 실행 검증

- Python 3.13.2, pandas 2.3.3, pyarrow 23.0.1 사용.
- 다운로드 스크립트의 Bash 문법 검사 통과. 실제 다운로드는 기존 원본을 사용하므로 재실행하지 않았다.
- ZU 원본 1,030행을 현재 코드로 파싱하고 1,243열로 결합한 뒤 `verify_merge.py`의 전체 행·값 검사를 통과했다.
- 기존 중간 Parquet 9개의 실제 행 수·컬럼 수가 보존한 품질 보고서와 일치함을 확인했다.
- 파일당 첫 10행씩 총 90행을 별도 임시 입력으로 만들어 기본 표 생성 실행 및 내장 저장값 검사를 통과했다. 유효 결과는 85행 × 113열이다.
- 기존 전체 기본 표가 822,419행 × 113열임을 확인했다. 첫 경기 피처를 재계산한 Parquet는 가져온 샘플과 완전히 일치했고 내장 검사 5개를 모두 통과했다.
- 전체 7개 포맷을 원본 로그부터 재생성하지는 않았다. 일부 포맷의 과거 행 수 차이는 여전히 별도 조사 대상이다.
