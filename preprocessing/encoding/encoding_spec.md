# 모델 입력과 인코딩 정의 (v1)

작성일: 2026-11-17. **정의한 규칙대로 세 분할의 인코딩·저장·전체 행 검증을 완료했다. 모델 학습은 아직 수행하지 않았다.**

## 1. 사용할 데이터와 컬럼

입력은 `data/datasets/splits/data/`의 `train.parquet`, `validation.parquet`, `test.parquet`다. 각 파일은 basic + stat + type + matchup을 포함한 기존 371열이다. 이미 정한 분할을 유지한다.

| 구분 | 원래 컬럼 수 | 처리 |
|---|---:|---|
| 각 슬롯의 포켓몬 종 | 12 | 슬롯별 원핫 인코딩 |
| 각 슬롯의 첫째·둘째 타입 | 24 | 슬롯·타입 위치별 원핫 인코딩 |
| 각 슬롯의 종족값 | 72 | 숫자 유지 |
| 능력치 조합 피처 | 54 | 숫자 유지 |
| 타입 구성 피처 | 51 | 숫자 유지 |
| 방어 상성 피처 | 153 | 숫자 유지 |
| `formatid` | 1 | 원핫 인코딩해 입력에 포함 |
| `battle_id`, `uploadtime` | 2 | 추적·분석용으로 보관, 첫 모델 입력에서 제외 |
| `winner` | 1 | 입력에서 제외. 결과를 직접 알려주므로 사용 불가 |
| `y` | 1 | 정답으로 분리. 1은 p1 승리, 0은 p2 승리 |

**변환 전 입력은 367개 컬럼**이다. 기존 입력 후보 366개에 `formatid`를 추가한다. 이 중 숫자 330개, 문자 범주 37개(종 12 + 타입 24 + 포맷 1)다. 업로드 시각은 원본 표에 보존하며 입력 선택 단계에서만 제외한다.

컬럼은 `stat_type_matchup_features/info/columns.json`의 `features` 순서 뒤에 `formatid`를 추가해 정한다. 정답·관리 정보와 입력은 별도로 저장한다. 원본 371열이나 기존 `columns.json`의 의미를 바꾸지 않는다.

## 2. 원핫 인코딩 규칙

원핫은 항목마다 칸을 만들고 해당하면 1, 아니면 0을 넣는 방식이다. 예를 들어 종 목록이 `[bulbasaur, charmander, squirtle]`이면 charmander는 `[0, 1, 0]`이다. 종에 1·2·3 같은 크기나 순위를 부여하지 않는다.

| 대상 | 미리 고정할 목록 | 변환 규칙 |
|---|---|---|
| 종 | 현재 `data/external/pokedex.csv`의 종 ID 701개 + `__UNKNOWN__` | 12개 슬롯 각각 같은 종 목록 사용. 도감에 없는 종은 UNKNOWN에 표시하고 건수·값 기록 |
| 첫 번째 타입 | 5세대 타입 17개 + `__UNKNOWN__` | 슬롯별 18개 칸. 필수 정보이므로 결측은 오류로 중단 |
| 두 번째 타입 | 5세대 타입 17개 + `__NONE__` + `__UNKNOWN__` | 슬롯별 19개 칸. null·빈 문자열은 단일 타입을 뜻하는 NONE으로 변환 |
| 포맷 | `gen5nu`, `gen5ou`, `gen5pu`, `gen5ru`, `gen5ubers`, `gen5uu`, `gen5zu` | 7개 칸. 대상 밖 값이나 결측은 오류로 중단 |

타입 17개는 `data/external/gen5_typechart.csv`의 공격 타입 목록을 사용한다. 타입 문자열은 앞뒤 공백을 제거하고 소문자로 맞춘다. 종 ID는 저장된 정규 종 ID를 사용하고, 별명을 임의로 종으로 변환하지 않는다. 종 결측도 오류로 처리한다. UNKNOWN은 값은 있지만 고정 사전에 없는 경우를 위한 항목이다.

각 목록은 사전순으로 고정하고 예약 항목은 뒤에 붙인다. 첫 범주를 버리지 않고 모든 범주를 보존한다. 변환 시 실제 목록·순서와 참조 파일 해시를 함께 저장한다. 검증·테스트에 새 항목이 나왔다고 목록을 늘리거나 열 순서를 바꾸지 않는다.

현재 도감 크기 기준 변환 후 입력은 다음과 같이 **9,205열**이다.

- 종: 12 × 702 = 8,424열
- 타입: 12 × (18 + 19) = 444열
- 포맷: 7열
- 숫자: 330열

대부분 0이므로 희소 행렬(CSR, float32)로 저장했다. 숫자 피처는 float32로 변환하면서 소수점 반올림 오차가 생길 수 있으며, 검사는 원본을 float32로 변환한 값과 대조한다. 모든 0을 CSV로 펼쳐 저장하지 않는다. 종·타입은 슬롯별 관계를 유지하며, 이번 버전에서 팀 멀티핫으로 합치지 않는다. 슬롯 순서에 따른 모델 예측 변화는 이후 평가 항목으로 남긴다.

## 3. 분할과 표준화 규칙

위 범주 목록은 경기 빈도나 승패가 아닌 고정된 참조 자료와 대상 포맷에서 정한다. 따라서 검증·테스트를 조사해 변환 규칙을 학습할 필요가 없다. 정답을 이용한 인코딩과 등장 빈도 인코딩은 이번 버전에서 사용하지 않는다.

숫자 피처는 우선 값을 유지한다. 모델 선택 후 표준화가 필요하면 **train의 평균·표준편차만으로** 변환 규칙을 정하고 validation·test에 그대로 적용한다. 원핫 값은 표준화하지 않는다. 표준편차가 0인 숫자 열의 처리와 스케일러도 실제 구현 시 기록한다.

## 4. 변환 결과와 검사

- `X_train`, `X_validation`, `X_test`: 같은 열 순서의 희소 입력 행렬
- `y_train`, `y_validation`, `y_test`: 각 입력 행과 같은 순서의 정답
- 경기 ID 대응표: 행 번호와 `battle_id`를 연결해 추적
- 변환 명세: 입력 목록, 범주 목록, 변환 후 피처 이름·순서, 참조 해시와 처리 버전
- 검사 보고서: 행 수·정답·경기 순서 보존, 모든 분할의 동일한 입력 열, 결측·무한값과 UNKNOWN 건수, 정답·제외 컬럼 미포함

2026-11-17 확인: 원래 입력 후보 366개는 종 12개·타입 24개·숫자 330개로 구분된다. train의 모든 종 ID는 현재 도감에 있으며, train에 대상 포맷 7개가 모두 있다. 이후 아래의 실제 변환·저장 검증까지 완료했다.
